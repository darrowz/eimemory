# Controlled business release lineage

The controlled release workflow records its actual six-domain release lineage
after replay, live acceptance and channel verification, before its final
stability window. A current deployment receipt alone verifies deployment; it
does not attest changed storage, governance, recall or evolution domains.

`memory.recall` may use the exact current signed
`eimemory.evaluation.controlled_production_acceptance` record. Its native
verifier rechecks the protected policy, HMAC, latest attempt, release identity,
all configured colleague scopes, original physical source versions and complete
retrieval. A newer failed attempt, changed source, incomplete search or wrong
owner cannot reuse an earlier successful record. This remains controlled
existing-memory recall and does not certify natural queries or autonomous
first discovery.

Other domains retain their original validators: durable replay manifests for
governance, exact canonical live cases for storage, the current channel receipt,
and the actual deployment receipt. Evolution changes retain the strict
transaction or existing independent automatic authorization requirement.
Missing authority, a revoked key or an invalid proof remains a failure.

The workflow records lineage and then independently reads it back under the
same explicit compatibility replay catalog. It requires `ok`, `validated` and
`compatible`, the exact stored record and the complete original gate set.
Revalidation failure blocks closure. Reports produced by 1.14.156 and later
cannot remove the required-lineage marker to fall back to the older contract.
Original historical reports keep their recorded contract.

Nightly creates a new signed controlled acceptance attempt. Before its native
L5 reading, an established controlled closure is revalidated against that
newest attempt and the native current-release replay cohort. This phase runs
no recall query, replay or live task. It rechecks all unchanged domains and
preserves original lineage and acceptance records. An initial release without
an established full closure remains explicitly awaiting that closure.

Business qualification and L5 completion remain separate claims. A valid
lineage does not produce a code transaction, terminal receipt, source novelty
fact or elapsed observation interval.
