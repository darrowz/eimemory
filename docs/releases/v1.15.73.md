# v1.15.73

## Summary
Keep Hermes cron and other operator-scoped explicit recalls from being rejected as `invalid_request`.

## Why
Cron sessions bind as the local operator, not the Feishu business user. `adapter.prefetch` then injected `acceptance_generated` into `task_context` while also setting it on `explicit_request`. Explicit recall accepts only `source_ids` in `task_context`, so the extra key raised and the bridge returned HTTP 400. Business-scoped chat recall was unaffected. A prefetch without `explicit_request` also succeeded.

## Changes
- Operator explicit prefetch still forces `explicit_request.acceptance_generated=true` and does not mutate the caller object.
- That flag is no longer copied into `task_context` on the explicit path. Non-explicit operator prefetch still marks `task_context`.
- Version / Hermes plugin.yaml → 1.15.73

- Redeploy tip via eimemory-deploy-worker and switch `/opt/eimemory/current`. Restart `eimemory-rpc` so the running process loads the new release; a Hermes gateway restart is needed only if the gateway pins the old adapter tree.
- This does not claim cron recall quality, L5, or release closure. The next 04:00 cron recall is the functional check.
