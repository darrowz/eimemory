# 1.15.88 — current enrollment and attributable learning inputs

This release adds a current-state registration path when historical control
materials are unavailable, and separates verified input provenance from weak
host callback labels. Historical keys and custody requirements remain intact.
It does not reconstruct past migration evidence or certify prior repairs.

## Current-user enrollment

The native operator explicitly reviews a bundle, settings, scope map, current
topology, source authority and native process snapshot. A complete private
write-ahead archive is published before control files change. Source-equals-
destination journals preserve their inode, mode, bytes and queued writers.
Recovery retains foreign changes and legitimate appended history. Nonce retries
do not issue a second birth key. A same-registry completion route can finish a
published epoch without discarding its genuine activation artifacts.

Incomplete current births block job, registry and controller mutations at
both public and internal entry points. Necessary observation and birth
attestation remain available. Legacy historical topology is a separate route.
Native snapshots select properties by loaded service, timer or path interface;
they preserve genuine field absence instead of supplying synthetic process IDs.
Loaded services still require their complete process and execution fields.
Current receipts retain `historical_custody_recovered=false`,
`release_accepted=false`, and `autonomous_repair_credit=false`. Initial managed
incident authority is disabled. Real unit, PID, socket and operational
acceptance must be verified after deployment.

## Input origin and learning credit

The native gateway supplies a revocable event/input capability. The collector
checks its thread, profile, actor, query, session and explicit host turn. A
separate private-producer RPC binds the claim to an existing scoped recall
decision. A domain-separated receipt HMAC protects the new metadata table.
Ordinary recall callers cannot promote their own input to an external source.
The feature is disabled by default and requires the separately reviewed native
companion plus `EIMEMORY_CAPTURE_INPUT_ORIGIN=1`.

Its bounded signed outbox has independent files and schemas. Mutations reload
authenticated disk state under a process lock; acknowledgements remove only
the exact sent item. Network I/O runs outside the disk lock. Old effect retry
ledgers and their phases remain unchanged. Older readers ignore the new table
and queue.

Legacy or unverifiable origin remains unknown. Reports retain these candidate
rows. New natural-data learning credit uses one earliest eligible input in the
retained exact namespace before time-window selection, so a later retry cannot
become a fresh independent sample merely by moving into another window.
Existing signed recall policy views and retrieval ranking paths are unchanged.

External-platform provenance does not prove human authorship, answer quality,
delivery or task success. The current collector observes matching post
callbacks; interrupted inputs without that callback remain unknown. Its
population is therefore the attested subset, not all admitted input coverage.
Edit revisions are distinct only when the native host supplies them.

## Answer and host compatibility

Answer observation v2 records separate full host, bounded pre-call and
normalized recall query digests. It uses the same normalization as the recall
decision and retains exact pre-call consistency checks. Complete callback
bodies remain digest-only observations. Historical v1 logs are not rewritten.

The new three-file companion pins actual retained live preimages, requires
absence of its new file, and advances the previous runner postimage. Its
manifest describes seven effective host paths together with inherited
lifecycle changes. The earlier five-file patch and its historical replay are
preserved. Installation of the Python package alone does not install this
native companion.

## Validation boundary

Independent review reproduced and fixed stale outbox overwrites, cross-window
double credit and mismatched multiline query digests. The origin/callback
Linux regression passes 344 cases. Its two Windows failures are reproduced on
the exact previous source: an existing POSIX permission assertion and a native
UID fixture. They are not silently removed or newly skipped.

The current-user enrollment Linux regression passes 713 cases with ten
platform/environment skips. Its 16 native-property cases include the nine
independently reviewed cases; these counts overlap. A read-only production
probe collected all 40 inspected units without enrolling or changing services.

The earlier deployed 1.15.87 operational closure passed its 15-case cohort,
three authenticated RPC checks and ten live checks. Its frozen independent
source suite retained 11/11, and the original synthetic RAW 200-question replay
retained Top-1 109/120 and Top-5 119/120 with no changed hit order or answerable
empty result. Candidate 1.15.88 must pass these guardrails and its own CI and
persisted native acceptance. These are not final-answer accuracy scores.

Historical private review retained the same eight selected identities.
Supplemental model-input evidence reconstructed three exact injections and
five matching rendered fragments. The bounded reviews do not provide complete
answer gold, external-delivery proof or memory causal benefit. No natural
answer accuracy or L5 certificate is asserted.
