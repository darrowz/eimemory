# eimemory 1.15.79 — ordinary-chat valid-time memory

## Delivered source behavior

The ordinary `Runtime` chat path enables temporal integration for native `sync_turn`, L1 extraction, `prefetch` and recall. This is not merely the separately opt-in structured temporal API from 1.15.78. It uses the existing canonical RuntimeStore/SQLite storage; no additional database or production data migration is introduced.

For supported, explicitly dated assertions, current queries select the currently valid value and historical queries select the value valid at the requested time. Comparisons and replacements remain confined to the same authorized owner, entity and attribute. Bounded corrections and retractions affect only their half-open effective interval. Historical source evidence remains intact; capture order does not determine business validity.

The versioned `ordinary_temporal_literals.v1` producer proposal supplies exact source literals. The backend locates their positions deterministically and preserves strict validation of the legacy span DTO. Model omissions, malformed proposals and same-date conflicting originals cannot silently turn an older value into a certain current answer. Original-source checks subtract certainty rather than manufacture replacement facts.

New default-off `MemoryAPI` readers, including evolution callers, withhold managed temporal bodies and remove stale derived hints instead of returning them as ordinary current evidence. Canonical source admission, exact scopes, full record digests, mandatory evidence and request-local proof isolation remain required.

Deployment verification reports bounded, allowlisted method/attempt/status/error categories. Explicit business or authorization refusals are not retried. URLs, response bodies, raw exception text, credentials, environment/context payloads and token hashes are excluded.

## Acceptance evidence

- Consolidated parent execution in an isolated, credential-free application environment: **630 tests and 60 subtests passed** on the final business-code candidate. This includes the original contracts, the seven parent reproductions and the added bounded-operation/default-reader/diagnostic cases.
- Independent read-only source review passed with no reported blocking security or logic finding. The review is source approval, not a deployment receipt.
- The existing configured `openai-codex / gpt-reserve / low` producer was invoked anew on the final business code: four transport calls succeeded, four current/historical queries were correct, and all four remained correct after reopening storage. These are repeated regression fixtures, not new blind questions or a general accuracy estimate.
- The separate rollback-compatibility continuation and its 72 static cases were removed from this release; they are not included in the passing counts.

## Limits and operational boundary

- The separate structured temporal API remains opt-in. Ordinary Runtime integration is enabled; these are different activation boundaries.
- Full knowledge-time (`known_at`) replay is not supported. Explicitly dated valid-time semantics do not establish general natural-language extraction accuracy.
- Unpatched old binaries reading a store populated by the ordinary temporal integration are **unsupported**. Old-binary rollback compatibility and its proposed new deployment fences were explicitly excluded from scope. This exclusion does not authorize stale snapshot restoration over later writes or otherwise unsafe rollback.
- Source tests and the small real-model sample do not establish production-profile latency, general retrieval quality, online host acceptance, 48-hour stability or L5 completion. Formal immutable deployment, live identity/receipt checks and post-switch acceptance remain separate requirements.
- The rejected experimental RAW ranking patch is excluded. No global model, other profile, capture-consent scope or credential configuration is changed by this release.
