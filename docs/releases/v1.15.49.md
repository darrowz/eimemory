# 1.15.49

Provider proposals now run the existing public-function wiring audit before becoming transaction candidates. The check compares tracked checkout sources with all proposed replacements in memory, rejects newly unwired functions or lost callers, and fails closed on unavailable sources. It executes no proposed code and creates no worktree. Scratch files cannot supply callers.

Final full-suite wiring, evidence, authorization, isolation and transaction gates remain unchanged. This early rejection prevents avoidable verification work; it does not certify a semantic recall repair, a successful repair transaction, or L5 completion.

Exact single-source recalls can now be observed with target tracing while retaining the original task context when no target-source override was saved. Multi-source requests still require an explicit target source. This changes diagnostic binding only, without changing retrieval or answer admission.
