# 1.15.85 — current-source qualification for controlled recall

A native controlled acceptance attempt passed 10 of 15 known-item cases.
Replaying those exact signed queries and targets reproduced 10/15. All five
missed targets reached hydration: four were withheld by temporal authority and
one by L1 parent validation. The benchmark had counted those records as positive
targets without applying the same current-authority checks used by recall.

This version shares source classification with the native temporal reader.
An unmarked legacy observation may retain its ordinary route only when the
original user clause supports the same literal undated scalar assertion, the
exact parent binding remains valid, and a complete family read establishes
that temporal authority has not reserved the slot. This retrospective check
does not rewrite the source or create a journal. Explicit unresolved or malformed
markers, uncertainty, unsupported statements, changed parents and unavailable
authority remain protected by the existing gates. New-write semantics are
unchanged.

Controlled benchmark generation now qualifies a target against current temporal
and source authority before it becomes a positive case. Qualification does not
depend on the question's title, retrieval score or a previous successful result.
Generation keeps exact scope/source restrictions, the creation cutoff, bounded
scanning and native ordering. Authority read failures remain distinct from known
inapplicability. Execution and CPA receipt verification recheck the same source;
explicit historical source grants do not silently substitute another target.

Ordinary candidates from authorized shared-owner and physical-alias scopes
retain their existing recall route. Managed temporal facts keep exact-owner
family checks. Read-time parent validation distinguishes a missing parent from
an existing parent whose payload or projection cannot be verified. The latter
makes authority unavailable and stops positive-case generation.

CPA observation retains the actual MemoryAPI instead of replacing its authority
context with a recall-only proxy. Nightly diagnostics preserve the qualification
reason codes. The project and Linux workflows include the new target suites and
the existing temporal grounding, reader-boundary and source-operation regressions.

Exact complete literal titles of verified temporal facts now use the same
member-specific source proof at the current business time. Historical questions
continue to resolve their requested business time. Obsolete, partial, changed
or future members still pass through the existing applicability checks.

## Validation

The signed original fifteen cases and queries remain frozen. Both the previous
release and this candidate return **10/15** on that original cohort. All five
withheld targets remain in the comparison. Four lack a currently certified
temporal assertion and one has an unavailable source parent.

The corrected positive-source qualification produces a separate cohort from
the same exact scopes, cutoff, ordering and case budgets. Native isolated CPA
execution passes **5/5 in each of three scopes**. Eleven additional existing
source cases were frozen before measured recall, excluding both the original
fifteen and the revised operational cohort. They include older eligible sources
and pass **11/11** with both previous and candidate source. One scope has only
one independent eligible case after these exclusions.

Independent synthetic qualification tests improve from **4/14 to 14/14**,
including real ordinary and temporal-title retrieval, legacy source links,
incomplete authority, bounded scanning, minimum case counts and exact historical
grants. A separate temporal regression suite passes **235 cases**. Local
benchmark, CPA and transport regression passes **383 cases with 6 platform
skips**. Collections overlap.

The original 200-question synthetic RAW replay retains Top-1 **109/120** and
Top-5 **119/120**, with zero complete hit-order changes and zero answerable
empty-candidate results. This measurement covers document ranking.

## Production verification

Deployment requires the exact release's saved native closure receipt. The
producer executes controlled recall, authenticated RPC, projection readiness,
replay, live acceptance, channel provenance, release lineage and a fresh
stability window. CI and deployment results are recorded in the release audit.
Natural answer quality, no-answer accuracy and L5 have their own qualification
contracts.
