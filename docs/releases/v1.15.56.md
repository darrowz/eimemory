# 1.15.56

Trusted production-recall baseline loading now soft-skips a newest active high-water tip that fails report contract validation (for example half-present engine identity fields) and falls back to an older active qualified record for the same high-water key. Absent high-water stays distinct from an invalid tip, allow_legacy exact-ranking semantics are unchanged, and a structurally valid not-qualified failed attempt still supersedes older accepted tips. Envelope or source-partition forgeries on the tip continue to fail closed.

Controlled production acceptance persistence binds the signed body and store envelope to the deployment receipt / policy primary owner when `receipt.scope` names that primary. Nightly may still authorize as an additional owner; L5 controlled lineage refresh, which reads under `receipt.scope`, then sees the current high-water. The public acceptance result exposes that persist `scope` so nightly re-verify uses the same partition. Fixtures without receipt scope keep per-caller envelopes so dual-owner isolation tests remain compatible.

These are prevention fixes for the 1.15.55 nightly business-acceptance failures (`baseline_report_contract_invalid` and receipt-owner CPA high-water mismatch). Deploy is required before the next nightly for the prevention to take effect on honrui; this package does not itself retire live store records or rewrite CPA high-water.
