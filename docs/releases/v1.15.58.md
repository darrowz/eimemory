# 1.15.58

Controlled stability now treats quiet oneshot units after `systemctl reset-failed` as ready: when ActiveState is inactive and Result is success, a stale ExecMainStatus from a prior failure no longer sets `allowlisted_unit_not_ready`. Active or activating oneshots still require ExecMainStatus=0, and failed oneshots remain rejected once writers are resumed. This unblocks post-deploy stability when nightly (or timer-monitor) left a sticky failed state that operators cleared with reset-failed.

This is a stability observation contract fix only. It does not re-run nightly, rewrite recall high-water, or claim business closure / L5 certification is green without a fresh closure reassessment.
