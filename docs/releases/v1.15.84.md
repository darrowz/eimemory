# 1.15.84 — native single-gateway acceptance

An ordinary release-acceptance CLI could fail to discover an existing protected
single-gateway declaration when no runtime-manager enrollment was present. It
then used the legacy multi-gateway inventory and failed before reading the
journal. Native profile observation also always required the manager, while
ordinary capture observation omitted the systemd invocation identity.

The current nonroot account can now discover its existing declaration from
fixed passwd-home coordinates. The original protected-file, operator-intent,
scope and digest checks remain in force. Managed execution contexts retain
their existing authority and transport; a declaration does not enroll a
manager, restore historical custody or authorize new memory scopes.

For ordinary native user observation, the runtime must be one of the two units
in the verified declaration. The observer binds systemd state to the account,
cgroup, process UID, start time, invocation and namespace identities, then
checks them again after reading bounded process metadata. Native profile proof
and capture proof use the same observation contract. A manager error never
selects this path as a fallback.

These changes do not waive business-profile coverage, capture allowlists,
attestation, retrieval health, database integrity, stability windows or later
release gates. An operator scope cannot stand in for a business user. Existing
configuration may therefore reveal a further coverage refusal once the correct
topology becomes visible. Production acceptance requires the saved result of
the exact deployed release; unit tests and a healthy service cannot certify it.

The 1.15.83 final registered-source and reranker-profile fixes are retained.
The original synthetic 200-question RAW fixture remains the recall guardrail:
109/120 at rank one and 119/120 within five, with no new answerable empty
candidate results. These measure document ranking, not final-answer accuracy.
Optional model answer-support assessment remains disabled by default.

The same 32 discovery cases improve from 11/32 on the prior release to 32/32
on Linux, including real filesystem permission, link and account boundaries.
Eight checks through the existing owner/capture consumers improve from 5/8 to
8/8. The dedicated process-observation suite passes 51 checks, including
managed-path denial, fixed-binary execution and process replacement refusal.
These checks qualify the observation code, not production business evidence.
