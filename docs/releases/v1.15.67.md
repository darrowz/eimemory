# 1.15.67

## Fix

- Code evolution no longer auto-routes sticky `release.closure_*` incidents whose
  detector reason / hard_errors are the oneshot-stability aggregate pair
  `sample_not_current_or_healthy` + `sample_unit_inventory_incomplete` (or the
  classic `allowlisted_unit_not_ready`) once live allowlisted JOB_UNITS are quiet.
  The 1.15.62 drop only matched `allowlisted_unit_not_ready`; assess emits the
  sample_* pair when a mid-window oneshot (often timer-monitor, itself failing
  because legacy learn-watch was failed) poisons a stability sample. Hermes then
  received an unpatchable gate-evidence plan and nightly CE exited
  `code_evolution_focused_verification_failed`.
- `select_current_system_incidents` now `reset-failed` allowlisted JOB_UNITS
  (and legacy learning oneshots) before the readiness drops, so sticky
  `Result=failed` bits do not keep the incident routed.
- `reset_failed_allowlisted_job_units` also clears legacy learning oneshots so
  timer-monitor does not immediately re-fail and reopen the stability defect.

## Ops note

- Does not invent release closure success or flip product L5 / natural labels.
- `src_auto_chatpaper_arxiv` stays disabled until upstream recovers.
