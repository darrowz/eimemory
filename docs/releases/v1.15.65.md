# 1.15.65

## Fix

- Code evolution no longer auto-routes sticky `release.closure_*` incidents whose
  detector reason was `post_replay_projection_not_ready` (or the related
  projection barrier invalid / post-acceptance variants) once the live
  controlled-projection wait reports `ok`. The 1.15.64 drop only fired for the
  sqlite not-applicable token; with postgres vector enabled the wait returns
  `ok=True` and an empty reason after lag clears, so Hermes kept receiving an
  ops-timing incident it cannot code-repair (`proposal_unwired_public_functions`).
- Release-closure post_replay wait now admits postgres_vector barriers with
  status `not_applicable` (disabled / not_configured) as ready, matching sqlite.

## Ops note

- Does not invent projection readiness; it only retires already-cleared lag
  incidents and avoids inventing repair-eligible ones when the barrier is
  explicitly not applicable.
