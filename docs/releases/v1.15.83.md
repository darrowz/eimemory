# 1.15.83 — final source admission and release-gate configuration

## Changes

A source can be revoked after recall selects its records. Final admission now
rechecks an existing server source-trust decision against the current registry,
using the same trust and binding contract as selection. Disabled, deleted,
rebound or insufficiently trusted sources invalidate selected body and citations.
Persisted brief parents follow the existing recursive evidence checks. Ordinary
unregistered memory and non-recall consumers keep their existing behavior. No
new retry or deadline extension is introduced.

The release-gate environment wrapper previously omitted five settings consumed
by the native reranker: `URL`, `REVISION`, `TEXT_CHARS`, `MIN_SCORE` and
`CALIBRATION`. Enabled configuration could fail before producing a closure
report, even when the RPC service had a complete valid configuration. These
five exact keys now pass through the existing allowlist. Profile order, legacy
names, identity validation, endpoint restrictions and unrelated credential
exclusion remain intact. Empty or invalid closure reports remain rejected.

## Validation and acceptance boundaries

The frozen source-admission tests improve from 7/18 to 18/18, preserving all six
positive cases. Independent scenarios improve from five passes/five incorrect
deliveries/two inconclusive to ten passes/zero incorrect deliveries/two
inconclusive. A separate brief-parent component check improves from 1/2 to 2/2.
The inconclusive cases are not counted as passed end-to-end acceptance.

The release-profile tests improve from 4/19 to 19/19 and exercise the real native
configuration class and wrapper execution boundary. A separate 20-check review
verifies field coverage, precedence and rejection of invalid configurations.
The new tests are included in the explicit project and Linux CI selections.

The original 200-question synthetic RAW replay has 120 answerable cases. Its
acceptance floor remains Top-1 109/120 and Top-5 119/120, with no new empty
answerable results or changed ranking from these authority/configuration fixes.
These are document-ranking measurements, not generated final-answer accuracy.
Optional model-based answer-support assessment remains disabled by default.

Eight registered records add approximately 1.94 ms median to final admission in
the isolated local microbenchmark. Ordinary memory adds no registry reads. This
is the cost of the missing authority check, not a performance improvement claim.

Production acceptance must use the normal installer and saved business-closure
receipt for the exact deployed commit. Unit tests and RPC health do not certify
that business closure or L5 passed. The already packaged Hermes host patch is
unchanged; applying it again is unnecessary when its exact after-images match.
The ten historical initialization alerts still lack individual recovery evidence.
