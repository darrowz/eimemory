# 1.15.82 — answer support, ownership and tool evidence

## Source changes

Ordinary RAW search continues to return related evidence. Optional answer-support
assessment separately checks whether the presented passages supply the requested
facts, steps or version coverage. Unknown or unavailable support does not erase
independently eligible related material. `EIMEMORY_RAW_ANSWER_SUPPORT_ENABLED`
remains off by default; this release does not silently enable a new model route.

Applicability covers explicit versions, date boundaries, validity and withdrawal
through candidate selection and citation delivery. Version enumeration permits
separate sources to contribute individual versions without treating one version
as proof of a continuous interval. Canonical source titles establish identity,
not missing facts. Support proofs bind the request, selected content and delivery;
tight budgets preserve safe related material while withholding unsupported claims.

Hermes providers expose strict, read-only compatible-session reuse and typed busy
ownership failure while retaining collision protection. Host cache construction
and manager transfer additionally require the pinned patch under
`integrations/hermes/host-patches/`. Plugin installation alone does not apply that
external host patch. Its baseline includes the existing snapshot integration;
matching the host commit alone is insufficient to authorize overwriting files.

OpenClaw signs successful verification receipts only from affirmative execution
evidence. Explicit failure, unknown state, nonexecution and conflicting exit
results veto success. Complete serialized JSON diagnostics use root/details
control paths; historical records and quoted documentation remain data. ANSI
SGR normalization affects verdict checks only, retaining the original signed
result digest. Session/run/tool binding and post-mutation verification remain.

Fallback citation collection leaves the caller's original recall bundle unchanged.
Explicit captures validate citation presentation alongside the rendered bundle;
the added sidecar no longer causes an otherwise valid Hermes capture to fail.
Release-impact classification includes the support modules and host patch package.

## Validation

- The frozen public 200-question RAW replay retains Top-1 **109/120** and Top-5
  **119/120**, with zero ordering changes or newly empty answerable searches.
- Prior answer-support validation covers 404 synthetic questions. No added
  answerable support rejection remained in the final paired run; this measures
  support assessment, not generated final answer correctness. Some gold-answerable
  cases still lack the necessary source facts.
- Recall/support/provider regression: **667 passed**. OpenClaw regression:
  **154 passed and 4 subtests passed**, including **74/74** receipt assertions
  (54 negative cases, 19 successful cases and one digest-integrity check).
- Independent tool cases: **6/16 before, 15/16 after**. All ten negative cases
  are safely rejected. A count-only result lacks affirmative success under the
  new contract and remains a recorded compatibility difference; its gold was
  not changed. Final replay reused the same frozen cases.
- The independent Hermes host patch passes **26/26** isolated caller/manager
  scenarios versus **2/26** on the copied original host. This is not a complete
  real-host admission/lease or production-session acceptance claim.
- A separate honrui native host regression runs the same 12 files before and
  after the patch: **117 passed, 0 failed, 4 macOS-only skips** on each side,
  with retries disabled. This does not prove recovery of the ten reported alerts.

## Remaining boundaries

Unresolved upstream issues include registered-source revocation during in-flight
delivery, terminal retry correlation loss, action-value lookup after unrelated
feedback, inconsistent success aliases in learning, and Codex workspace fallback
alignment. This release does not claim those issues fixed.

Model support can vary and unavailable review remains unknown. The latest ten
reported Hermes initialization warnings lack per-event evidence. Synthetic tests,
service health and successful deployment each have separate acceptance scopes;
none establishes final-answer accuracy, L5 maturity or sustained performance.
