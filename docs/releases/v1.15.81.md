# 1.15.81 — scoped fact-citation delivery

## Scope

Add a bounded fact-citation gate and its real Hermes consumers while retaining the 1.15.80 RAW ranking baseline and 1.15.79 ordinary-chat valid-time integration. Default RAW exploration is unchanged. The explicit kernel request is `task_context.evidence_intent='fact_citation'`; ordinary Hermes consumers select this intent on the server for their separate RAW lane, without replacing structured L1 recall.

The lane reports **related**, **reject**, or **unavailable**. Relatedness is not semantic entailment. Rejection withholds RAW citations only within the declared RAW request scope; independently valid L1/temporal knowledge remains usable. Unavailable means verification could not be completed, not that all memory lacks an answer.

## Real consumer boundaries

- Normal prefetch carries a bounded `raw_citation` receipt through compact serialization and final rendering, including zero-evidence outcomes.
- Eligible proactive delivery keeps the original L1 context and acknowledgement namespace separate from RAW. RAW uses a request-bound sidecar and does not bypass control, deferral, source consent, empty-decision or existing fallback rules.
- Before initial **and repeated** proactive RAW consumption, the host obtains independent current policy/release metadata through the authenticated service, using pending request parameters rather than the response being checked. Missing, stale or mismatched metadata withholds RAW only; the response cannot establish its own initial expected release.
- Current and historical values, source withdrawal, uncertainty, cached decisions and persistence retain existing canonical/current-evidence admission. An unbound ordinary-chat RAW transcript cannot borrow the proof of its derived L1 fact.
- RPC `preserve_scope` constrains the exact scope before candidate collection and proof construction. Task/status/history restrictions reuse the existing server-derived mode.
- L1 receives render/compact budget priority. RAW excerpts are escaped untrusted data and are dropped first; explicit presentation metadata distinguishes a prepared receipt from material actually delivered to context.

## Evidence domain and limits

The normal/proactive lane declares `frozen_raw_request_scope.v1`: the existing RAW request scope, already authorized shared-owner behavior and enclosing exact/source/kind/deadline ceilings. This is not the potentially broader L1 logical user/legacy-alias union. A full explicit engine-union request whose owner set cannot be matched remains `unavailable` under `requested_engine_union.v1`; it is not silently relabelled or broadened.

Both canonical snapshots must cover the complete declared domain. The gate retains the 500 selected-row limit, including selected legacy `memory` rows before quality filtering, cooperative 0.5-second additional CPU budget and inherited remaining request deadline of no more than three seconds. Overflow, incomplete snapshots, source changes or insufficient remaining time are unavailable, not successful rejection. Owners or kinds are not discarded to fit the limit. Configured structured-admission/verifier requirements can also withhold this separate RAW lane.

The snapshots, source checks and independent delivery metadata are bounded observations, not an ABA-proof transaction over future writes. No global model route, capture consent, profile configuration, old-binary compatibility fence or data migration is introduced.

## Validation and interpretation

The unchanged, repeatedly used public 200-question retrieval regression fixture retains answerable Top-1 **109/120** and Top-5 **119/120**. Default RAW correctly returns empty for **0/80** no-answer questions; explicit fact-citation gating correctly returns empty for **5/80**, without an added answerable empty result or admitted reorder. The observed five gains are English; this fixture does not establish a Chinese no-answer improvement. These are retrieval results, not end-to-end model-answer accuracy or a new blind benchmark.

The consolidated acceptance covers the real Runtime/RPC/Hermes path, first and repeated delivery, independent policy/release metadata failures and changes, exact scope, source/owner exclusion, task/history restrictions, 501-row overflow, L1 preservation, current/history/withdrawal/reopen behavior, compact limits and unchanged isolated-renderer contracts. The initial stale-release boundary was also reproduced using a genuine service-generated response before its independent expectation was fixed.

Source regression, independent source approval, version/packaging verification and immutable deployment receipts are separate gates. Static producer checks or a process exit code do not replace any of them. Source/package acceptance does not certify production latency, comprehensive answer quality, L5 or a completed 48-hour observation period. Failed answer-form support filtering remains excluded; no additional score-optimization round is included.
