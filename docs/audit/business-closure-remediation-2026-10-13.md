## 保持的边界

- 正式最低 3 条及标签信任、发布权威、权限、grounding、错误召回和其他质量指标未降低。空候选、smoke、受控 known-item、诊断成功仍不能冒充正式自然问法标签。
- Hermes outbox 可以恢复同一次持久 capture；宿主不提供事件 ID 时，无法识别两个独立匿名 callback 是否属于同一真实事件。不得用正文一致替代事件身份。
- Persona 的消费 ledger 不单独裁剪，否则旧纠正会重新可消费。状态及恢复意图使用现有受限原子 JSON 文件机制；原生审计恢复失败时保留 pending，不报完成。历史已发生的重复 delta 不自动逆转。
- 备份的归档引用与各 SQLite 快照一致。辅助 JSON、配置、逻辑导出及不同数据库仍可能来自不同时间点，不能声称跨库原子快照。恢复时将备份 `sqlite/` 整体还原为新 Runtime 的 `state/`，包含 `payload_segments/`；只复制数据库文件不构成完整恢复。
- 旧 independent-evidence catalog 的 enforce/shadow 适用于显式独立验证入口；普通召回默认本地准入、交付后语义评审。单独配置的 REQUIRED verifier 仍在交付前阻断无证明结果，真实 canonical 撤回仍由最终权威读回拒绝。
- 本地模拟严格补丁事务的最终外部执行器没有生产副作用。代码修复不能代替实际受保护的补丁部署、观察期或回滚验收。

## 验证记录

全仓回归另外发现两条基线已有的 ARCH-01 向上依赖，已在独立导出的原始提交上复现。共享的有限数值校验及显式任务范围判断移到 `contracts` 底层，原 `scoring` / `recall` 导入路径保留同一函数的兼容导出；没有增加架构白名单或提高影子依赖上限。

完整回归还定位了原有运行路径的问题：能力迁移入口补齐 RuntimeStore 原生锁；能力看板的任务类型计数与其 release/lineage 样本使用同一过滤集。否则迁移会在连接所有权检查处失败，类型覆盖也可能混入被排除的其他客户端或版本。相关原生回归保留这些拒绝与范围边界。

规则晋升的交互 API 与 nightly 共用确定性证据选择：在精确规则和 scope 内，采用实际 UTC 事件时间；同刻冲突优先拒绝，不由随机 ID 决定。只有明确较新的有效通过证据才能解除此前阻断；基线诊断仍不能充当行为回放。原生持久化及实际 `apply=True` 消费测试同时验证拒绝和后续合法晋升。

普通 RPC 召回及 L0 搜索补齐既有 compact 预算异常处理；最终 loadout 添加证据和身份字段后，再次使用既有 validator 检查。仍采用 4 KB / 16 KB 上限；超限返回结构化不可用，不删除必需字段来制造通过。

评审游标写入补齐 RuntimeStore 的原生身份元数据，并保留已解析的精确 scope。身份修复不再把游标当成旧记录改写；新增回归同时验证原生元数据、修复前后不变、CAS 冲突与重启续扫。

存储归档的已应用 schema 标记与后来新增的待归档数据分别检查。CLI 状态及迁移调度现在遵守已有 `pending_archival` 进度，写入时刷新缓存，迁移完成后清除待办；离线快照要求保持。Persona 文件视图也明确使用传入的 PathLike 目录，避免误把 `Path.root` 当成数据目录。

旧测试的环境和契约假设分别修正：显式配置测试用户别名；纯模块导入检查在独立进程进行；研究材料正向夹具补充既有门禁要求的置信度；外部标签保留既定原值；发布摘要测试实际改变版本及动态定位描述行。没有靠放宽质量、安全或持久化断言使旧夹具通过。
